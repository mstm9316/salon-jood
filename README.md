## تشغيل محلياً
1. ثبّت Node.js إصدار LTS.
2. انسخ `.env.example` إلى `.env` وأدخل بيانات Supabase.
3. نفّذ:
   ```bash
   npm install
   npm run dev
   ```
4. للبناء:
   ```bash
   npm run build
   ```
   الملفات المنشورة ستكون داخل `dist/`.

## إعداد Supabase
1. أنشئ مشروعاً جديداً في Supabase.
2. افتح SQL Editor ونفّذ `supabase/schema.sql`.
3. من Authentication أنشئ حساب المدير وحساب موظف الاستقبال (لا يوجد تسجيل عام).
4. انسخ UUID لكل مستخدم من Authentication ثم أضف الملف الشخصي في SQL Editor:
   ```sql
   insert into public.profiles(id, full_name, role)
   values ('UUID-OF-OWNER', 'مدير صالون جود', 'owner');
   ```
   كرر لموظف الاستقبال مع `role='reception'`.
5. انسخ Project URL و anon/public key إلى متغيرات البيئة في Netlify:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`

## النشر على Netlify
1. ارفع مجلد المشروع إلى مستودع GitHub خاص.
2. في Netlify اختر Add new site > Import an existing project.
3. اختر المستودع، واجعل Build command=`npm run build` و Publish directory=`dist`.
4. أضف متغيرات البيئة أعلاه ثم Deploy.
5. بعد النشر، اختبر رابط الموقع من هاتفين.

## حدود النسخة الحالية – اقرأ قبل الاستخدام الفعلي
هذه حزمة مصدر أولية وليست خدمة منشورة أو متصلة بحسابات فعلية. لا يمكن تأكيد تشغيل الحجوزات حتى تضيف مفاتيح Supabase وتنفذ SQL.

- إرسال طلب الحجز وإضافة دور للانتظار متاحان بعد الربط.
- موافقة الإدارة وتعديل الخدمات متاحان من لوحة الإدارة بعد إعداد الحسابات.
- يوجد قيد PostgreSQL من نوع exclusion يمنع تداخل الحجوزات المعلقة والمؤكدة على مستوى قاعدة البيانات، إضافةً إلى فحص الأوقات في الواجهة.
- صفحة متابعة الزبون برقم الهاتف غير مفعلة بشكل آمن في هذه النسخة؛ لا نعرض بيانات العملاء للعامة لأن رقم الهاتف وحده ليس إثبات هوية. يلزم لاحقاً تفعيل OTP/SMS أو رمز متابعة سري لكل حجز.
- صفحة الموظفين الحالية تعرض حسابات الإدارة فقط؛ إدارة ملفات الحلاقين والجدولة متعددة الحلاقين تحتاج مرحلة لاحقة.
